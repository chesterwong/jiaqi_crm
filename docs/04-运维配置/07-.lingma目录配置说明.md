## 🎯 为什么需要重命名？

### 官方规范要求

根据通义灵码官方文档：

> **项目专属规则（Project Rules）**  
> 通义灵码支持项目专属规则的设定，这些规则存储在 `.lingma/rules` 目录下，仅对当前工程生效。

### 关键区别

| 目录名 | 是否被 Lingma 识别 | 是否自动生效 |
|--------|------------------|------------|
| `.qoder/rules/` | ❌ 否 | ❌ 否 |
| `.lingma/rules/` | ✅ 是 | ✅ 是 |

### 规则触发机制

Lingma 支持 4 种规则类型：

1. **Always（始终生效）** ⭐
   - 头部配置：`trigger: always_on`
   - 适用场景：所有 AI 对话和代码生成
   - 当前规则：所有规则都使用此类型

2. **Model Decision（模型决策）**
   - 头部配置：`trigger: model_decision`
   - 适用场景：AI 根据描述自动判断是否应用

3. **Specific Files（特定文件）**
   - 头部配置：`trigger: specific_files` + `files: "*.py"`
   - 适用场景：只对特定文件类型生效

4. **Manual（手动引入）**
   - 头部配置：`trigger: manual`
   - 适用场景：需要在对话中通过 `#rule` 手动引入

---

## 📝 规则文件格式

### 标准格式
```markdown
---
trigger: always_on
---
# 规则标题

> 优先级: ⭐⭐⭐⭐⭐
> 适用范围: xxx

## 一、规则内容
...

## 二、禁止行为
...
```

### 关键字段说明

| 字段 | 值 | 说明 |
|------|-----|------|
| trigger | always_on | 始终生效（推荐） |
| trigger | model_decision | 模型自动决策 |
| trigger | specific_files | 特定文件生效 |
| trigger | manual | 手动引入 |

## 🔄 与 Lingma 记忆的关系

### 两种机制对比

| 特性 | `.lingma/rules/` | Lingma 记忆 |
|------|-----------------|------------|
| 存储位置 | 项目目录 | 用户缓存目录 |
| 版本控制 | ✅ 可提交 Git | ❌ 本地存储 |
| 团队共享 | ✅ 是 | ❌ 否 |
| 自动生效 | ✅ 是（需正确配置） | ✅ 是 |
| 更新方式 | 编辑文件 | 对话更新 |
| 适用场景 | 团队规范 | 个人偏好 |

### 最佳实践

✅ **同时使用两种方式**：
- `.lingma/rules/` → 团队共享的开发规范
- Lingma 记忆 → 个人开发习惯和补充规范

## ⚠️ 注意事项

### 1. 文件大小限制
- 单个规则文件最大 **10,000 字符**
- 超过部分将自动截断

### 2. 规则冲突
- 如果规则与记忆冲突，**规则优先**
- 建议保持规则和记忆的一致性

### 3. IDE 版本要求
- VS Code 插件：v2.5.16+
- JetBrains 插件：v2.1.5+
- Visual Studio 插件：v0.4.4+

### 4. 刷新规则
- 修改规则文件后，可能需要重启 IDE
- 或在通义灵码设置中点击"重新加载规则"
