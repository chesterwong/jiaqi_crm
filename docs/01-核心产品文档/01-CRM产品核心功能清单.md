## 一、产品定位

### 1.1 核心定位
轻量级本地化CRM系统，支持客户全生命周期管理：
- ✅ 私有本地存储，数据物理隔离
- ✅ 局域网内部使用，零运维
- ✅ Docker Compose一键部署
- ✅ 数据驱动决策，覆盖线索→成交→服务→续约

### 1.2 目标用户（6种角色）

| 角色 | 权限级别 | 核心职责 | 数据访问范围 |
|------|---------|---------|-------------|
| 超级管理员 | 系统级 | 全局配置、用户权限、审计 | 全系统无限制 |
| 部门经理 | 部门级 | 团队监控、资源分配、审核 | 本部门及下属 |
| 销售代表 | 个人级 | 客户开发、跟进、签约 | 个人负责+团队池 |
| 市场人员 | 市场级 | 活动策划、线索获取、ROI分析 | 市场活动、线索数据 |
| 客户成功人员 | 服务级 | 健康度监控、续约增购、满意度 | 成交客户数据 |
| 财务人员 | 财务级 | 合同审核、回款核销、报表 | 合同、付款、回款数据 |

### 1.3 核心使用场景

**销售代表**：接收线索→跟进客户→记录沟通→推进漏斗→生成报价→签署合同→跟踪回款

**部门经理**：查看团队漏斗→识别瓶颈→分配公海客户→监控跟进及时性→审核报价合同

**市场人员**：策划活动→获取线索→自动化培育→分配高意向线索给销售→分析渠道ROI

**客户成功**：监控健康度→预警风险客户→主动关怀→挖掘续约增购→提升满意度

**财务人员**：跟踪付款计划→核销回款→预警逾期→生成现金流报表

**超级管理员**：配置权限规则→管理用户→查看全系统报表→制定业务规则

#### 3.3.2 新建/编辑客户档案
**功能描述**:客户信息录入、字段校验、历史追溯、智能填充、自动化数据链

**业务场景**:
销售录入新客户时,系统应该:
- 自动填充工商信息(输入信用代码自动查询)
- 智能推荐行业标签(基于企业名称AI识别)
- 实时校验数据准确性(信用代码格式/唯一性)
- 记录每次修改历史(审计追溯)

**验收标准**:
1. 公司名称唯一性校验,不允许重复
2. 信用代码18位格式校验,必须符合国家标准
3. 历史追溯记录每次修改,包含字段、前后值、操作人、时间
4. 支持添加多个联系人,每个联系人可设置角色
5. 地址支持高德地图集成,自动获取GPS坐标

#### 3.3.5 客户资源池管理
**功能描述**：三级池体系、保护期、回收规则、智能分配

**业务场景**:
销售经理每天需要:
- 查看团队池中的客户,分配给合适的销售
- 监控保护期到期客户,避免流失到公海
- 分析回收数据,优化分配策略
- 公海池中抢优质客户(先到先得)

**业务规则**:
```
新客户分配 → 进入个人池(7天保护期)
  ↓
保护期内: 不可被他人抢占、不可被系统回收
  ↓
保护期到期: 自动回收至团队池
  ↓
团队池30天无跟进: 回收至公海池
  ↓
公海池: 所有销售可领取
```

**保护期机制**:
- 新分配客户享有7天保护期
- 保护期内不可被他人抢占
- 保护期内不可被系统回收
- 保护期倒计时显示(剩余天数)

**自动回收规则**:
- 30天无跟进记录自动回收
- 回收路径: 个人池 → 团队池 → 公海池

**分配优先级**:
1. 历史成交率(最高优先级)
2. 跟进频率
3. 客户匹配度

**界面布局设计**:
```

│ 客户资源池                                    [批量分配] [统计] │
```

**技术实现示例**:
```python
# Python爬虫示例 - 工信部制造业企业数据抓取
import requests
from bs4 import BeautifulSoup
import time

class MIITCompanyCrawler:
    """工信部制造企业数据抓取器"""
    
    def __init__(self):
        self.base_url = "https://www.miit.gov.cn"
        self.session = requests.Session()
        self.session.headers.update({
            'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64)'
        })
    
    def crawl_manufacturing_companies(self, industry: str):
        """
        抓取制造业企业公示信息
        
        Args:
            industry: 行业类型 (纸品/彩印/软包装)
        
        Returns:
            企业列表
        """
        companies = []
        
        # 遵守robots.txt，控制请求频率
        time.sleep(2)  # 每次请求间隔2秒
        
        response = self.session.get(
            f"{self.base_url}/data/{industry}",
            timeout=10
        )
        
        if response.status_code == 200:
            soup = BeautifulSoup(response.text, 'lxml')
            # 解析企业数据
            for item in soup.select('.company-item'):
                company = {
                    'name': item.select_one('.name').text,
                    'credit_code': item.select_one('.credit-code').text,
                    'industry': item.select_one('.industry').text,
                    'scale': item.select_one('.scale').text,
                    'source': '工信部公示数据'
                }
                companies.append(company)
        
        return companies
    
    def save_to_crm(self, companies: list):
        """保存到CRM系统，自动去重"""
        for company in companies:
            # 基于信用代码去重
            existing = self.check_duplicate(company['credit_code'])
            if not existing:
                self.import_to_crm(company)
```

## 四、业务规则与逻辑

### 4.1 客户资源池流转规则
```
新客户入公海 
  → 按优先级自动分配（历史成交率>跟进频率>客户匹配度）
  → 个人池（7天保护期）
  → 超期/无跟进回收至团队池
  → 团队池超期回收至公海
```

### 4.2 销售漏斗阶段流转规则
- 销售代表只能向前推进阶段
- 管理员可回退阶段
- 阶段变更全程留痕
- 超期停留自动升级提醒

### 4.3 跟进提醒与升级规则
- 基于客户级别设定提醒频率（A类3天、B类7天、C类15天）
- 超过设定时间50%未跟进，提醒级别升级（普通→重要→紧急）
- 紧急提醒通知上级

### 4.4 报价审批规则
- <10万：直接提交
- 10-100万：部门经理审批
- >100万：总经理审批
- 审批超时自动升级

### 4.5 合同付款逾期规则
- 到期未付自动变更为"逾期"并通知
- 逾期超7天：通知部门经理
- 逾期超30天：通知总经理

### 4.6 数据权限隔离规则
严格遵循RBAC模型：
- 销售代表：个人负责客户+团队池共享客户
- 部门经理：本部门及下属所有数据
- 超级管理员：全系统数据无限制

### 4.7 客户动态时间线规则
- 聚合展示所有客户相关事件
- 不可删除，形成完整历史
- 按时间倒序展示

| 场景 | 异常情况 | 处理方式 |
|------|---------|---------|
| 批量导入 | 信用代码重复/必填字段缺失/文件过大 | 标记失败，提示行号与错误原因，支持下载错误报告 |

| 地理位置 | 用户拒绝授权或获取失败 | 允许跳过位置记录，开放手动输入地址 |
| 权限变更 | 用户正在登录时权限被修改 | 当前会话不中断，权限在下一次操作或重新登录时生效 |
| 数据导出 | 导出数据量过大 | 切换为异步生成任务，完成后通过站内信通知下载链接 |
| AI标签生成 | 客户数据不足 | 跳过自动标签生成，提示"数据不足，无法生成自动标签" |

## 五、核心设计原则

### 5.1 客户场景核心

**每一个功能都必须回答3个问题**:
1. 这个功能服务于哪个客户场景?
2. 这个功能如何帮助销售/客户成功更好地服务客户?
3. 如果没有这个功能,客户体验会受到什么影响?

**如果回答不上来,就不要做!**

### 5.2 自动化优先

**能自动的绝不手动**:
- 数据自动流转(线索→商机→合同→订单→回款)
- 任务自动创建(超时/到期/异常自动触发)
- 通知自动发送(微信/邮件/系统消息)
- 报告自动生成(日报/周报/月报)

### 5.3 AI深度融入

**AI不是噱头,是真正提升效率**:
- 智能填表(节省70%录入时间)
- 智能推荐(提升30%转化率)
- 智能预警(降低40%流失率)
- 智能分析(提升80%决策效率)

### 5.4 未来可扩展

**底层扎实,后续迭代强大**:
- 模块化设计(每个模块独立,可单独升级)
- API优先(所有功能都有API,方便集成)
- 数据驱动(所有决策基于数据,不是拍脑袋)
- 预留接口(未来扩展无需重构)
