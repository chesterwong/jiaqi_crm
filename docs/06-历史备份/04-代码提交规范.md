# 代码提交规范

## 一、Git分支管理规范

### 1.1 分支模型

```
main (生产分支)
  ↑
develop (开发分支)
  ↑
feature/* (功能分支)
  ↑
hotfix/* (紧急修复分支)
```

### 1.2 分支说明

| 分支 | 用途 | 命名规范 | 生命周期 |
|------|------|---------|---------|
| `main` | 生产环境代码 | 固定名称 | 永久 |
| `develop` | 开发环境代码 | 固定名称 | 永久 |
| `feature/{模块}-{功能}` | 新功能开发 | `feature/customer-crud` | 合并后删除 |
| `hotfix/{问题描述}` | 生产环境紧急修复 | `hotfix/login-error` | 合并后删除 |
| `release/{版本号}` | 版本发布 | `release/v1.0.0` | 发布后删除 |

### 1.3 分支操作流程

#### 功能开发流程

```bash
# 1. 从develop创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/customer-crud

# 2. 开发完成后提交
git add .
git commit -m "feat(customer): 实现客户管理CRUD功能"

# 3. 推送到远程
git push origin feature/customer-crud

# 4. 创建Pull Request合并到develop
# 5. 合并后删除功能分支
git branch -d feature/customer-crud
```

#### 紧急修复流程

```bash
# 1. 从main创建修复分支
git checkout main
git pull origin main
git checkout -b hotfix/login-error

# 2. 修复完成后提交
git add .
git commit -m "fix(auth): 修复登录失败问题"

# 3. 合并到main和develop
git checkout main
git merge hotfix/login-error
git checkout develop
git merge hotfix/login-error

# 4. 删除修复分支
git branch -d hotfix/login-error
```

## 二、Commit Message规范

### 2.1 格式规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 2.2 类型说明

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(customer): 添加客户导入功能` |
| `fix` | 修复bug | `fix(auth): 修复token过期问题` |
| `docs` | 文档更新 | `docs(api): 更新接口文档` |
| `style` | 代码格式 | `style: 统一代码缩进` |
| `refactor` | 重构 | `refactor(service): 优化查询逻辑` |
| `perf` | 性能优化 | `perf(list): 优化列表查询速度` |
| `test` | 测试代码 | `test(customer): 添加客户服务测试` |
| `chore` | 构建/工具 | `chore: 更新依赖版本` |
| `revert` | 回滚 | `revert: 回滚错误提交` |

### 2.3 作用域说明

| 作用域 | 说明 |
|--------|------|
| `customer` | 客户管理模块 |
| `followup` | 跟进管理模块 |
| `opportunity` | 商机管理模块 |
| `product` | 产品管理模块 |
| `dashboard` | 仪表盘模块 |
| `system` | 系统管理模块 |
| `auth` | 认证授权 |
| `api` | 接口相关 |
| `ui` | 界面相关 |
| `config` | 配置相关 |
| `deps` | 依赖相关 |

### 2.4 提交示例

```bash
# 功能提交
git commit -m "feat(customer): 实现客户列表分页查询

- 添加客户列表接口
- 实现分页查询逻辑
- 添加企业名称模糊搜索
- 添加客户等级筛选

Closes #123"

# 修复提交
git commit -m "fix(auth): 修复登录状态判断错误

修复了token过期后未正确跳转到登录页的问题

Fixes #456"

# 文档提交
git commit -m "docs(api): 更新客户管理接口文档

- 补充请求参数说明
- 添加响应示例
- 更新错误码说明"

# 重构提交
git commit -m "refactor(service): 优化客户查询性能

- 添加数据库索引
- 优化SQL查询语句
- 添加查询缓存"
```

## 三、Pull Request规范

### 3.1 PR标题格式

```
[<类型>] <模块>: <简要描述>
```

示例：
- `[Feature] customer: 实现客户管理CRUD功能`
- `[Bugfix] auth: 修复登录失败问题`
- `[Docs] api: 更新接口文档`

### 3.2 PR描述模板

```markdown
## 变更说明
[描述本次PR的主要变更内容]

## 变更类型
- [ ] 新功能
- [ ] Bug修复
- [ ] 文档更新
- [ ] 代码重构
- [ ] 性能优化
- [ ] 测试代码

## 相关Issue
Fixes #[Issue编号]

## 测试说明
[描述如何测试本次变更]

## 检查清单
- [ ] 代码遵循项目规范
- [ ] 已通过本地测试
- [ ] 已更新相关文档
- [ ] 已添加必要的注释
```

### 3.3 PR审查 checklist

- [ ] 代码符合命名规范
- [ ] 代码符合代码规范
- [ ] 已添加必要的注释
- [ ] 已添加必要的测试
- [ ] 没有明显的性能问题
- [ ] 没有安全漏洞
- [ ] 文档已同步更新

## 四、版本号规范

### 4.1 语义化版本

```
主版本号.次版本号.修订号
```

| 版本号 | 说明 | 示例 |
|--------|------|------|
| 主版本号 | 不兼容的API修改 | `2.0.0` |
| 次版本号 | 向下兼容的功能新增 | `1.1.0` |
| 修订号 | 向下兼容的问题修复 | `1.0.1` |

### 4.2 版本标签

```bash
# 创建版本标签
git tag -a v1.0.0 -m "发布v1.0.0版本"

# 推送标签到远程
git push origin v1.0.0

# 推送所有标签
git push origin --tags
```

## 五、提交频率建议

### 5.1 提交原则

- **频繁提交**: 小步快跑，每次提交完成一个独立的功能点
- **原子提交**: 一次提交只做一件事
- **清晰描述**: 提交信息清晰描述变更内容

### 5.2 提交时机

| 场景 | 建议 |
|------|------|
| 完成一个功能点 | 立即提交 |
| 修复一个bug | 立即提交 |
| 重构一段代码 | 单独提交 |
| 下班前 | 提交当天工作 |
| 切换任务前 | 提交当前进度 |

## 六、常用Git命令

### 6.1 基础命令

```bash
# 克隆项目
git clone <repository-url>

# 查看状态
git status

# 添加文件
git add <file>
git add .                    # 添加所有变更

# 提交变更
git commit -m "message"
git commit -am "message"     # 添加并提交

# 推送代码
git push origin <branch>

# 拉取代码
git pull origin <branch>
```

### 6.2 分支命令

```bash
# 查看分支
git branch                   # 本地分支
git branch -r                # 远程分支
git branch -a                # 所有分支

# 创建分支
git branch <branch-name>
git checkout -b <branch-name>

# 切换分支
git checkout <branch-name>

# 合并分支
git merge <branch-name>

# 删除分支
git branch -d <branch-name>  # 已合并
git branch -D <branch-name>  # 强制删除
```

### 6.3 撤销操作

```bash
# 撤销工作区修改
git checkout -- <file>

# 撤销暂存区
git reset HEAD <file>

# 修改最后一次提交
git commit --amend

# 回退到指定版本
git reset --hard <commit-id>
```
