## 一、模块概述

### 1.1 功能目标

客户管理模块用于管理制造业企业的客户信息，支持客户档案的增删改查、联系人管理、客户标签、资源池管理等功能。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| 客户 | 与企业有业务往来的企业客户 |
| 联系人 | 客户方的对接人员 |
| 公海池 | 未被任何销售人员负责的客户集合 |
| 私海池 | 已被销售人员领取的客户集合 |
| 客户等级 | 根据客户价值划分的等级（A/B/C） |

### 2.2 客户列表查询

#### 2.2.1 功能描述

提供客户列表的分页查询功能，支持多条件筛选和排序。

#### 2.2.2 业务规则

1. 列表默认按创建时间倒序排列
2. 支持按企业名称模糊搜索
3. 支持按客户等级、客户状态、负责人筛选
4. 分页默认每页20条，可选10/20/50/100
5. 销售人员只能查看自己负责的客户（管理员除外）

#### 2.2.3 输入项

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| page | Integer | 否 | 页码，默认1 |
| size | Integer | 否 | 每页数量，默认20 |
| companyName | String | 否 | 企业名称关键字 |
| customerLevel | String | 否 | 客户等级：A/B/C |
| customerStatus | String | 否 | 客户状态 |
| ownerId | Long | 否 | 负责人ID |

#### 2.2.4 输出项

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Long | 客户ID |
| customerCode | String | 客户编号 |
| companyName | String | 企业名称 |
| customerLevel | String | 客户等级 |
| customerLevelName | String | 客户等级名称 |
| customerStatus | String | 客户状态 |
| ownerId | Long | 负责人ID |
| ownerName | String | 负责人姓名 |
| contactName | String | 主要联系人姓名 |
| phone | String | 主要联系人电话 |
| createdTime | DateTime | 创建时间 |

3. 支持按客户等级筛选
4. 分页功能正常
5. 数据权限控制正确

### 2.3 客户详情查看

#### 2.3.1 功能描述

查看客户的完整信息，包括基础信息、联系人、跟进记录、商机等。

#### 2.3.2 业务规则

1. 详情页以标签页形式展示不同信息
2. 基础信息标签页：展示客户基本信息
3. 联系人标签页：展示客户联系人列表
4. 跟进记录标签页：展示客户跟进历史
5. 商机标签页：展示客户相关商机

#### 2.3.3 输入项

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Long | 客户ID |
| customerCode | String | 客户编号 |

| creditCode | String | 统一社会信用代码 |

### 2.4 新增客户

#### 2.4.1 功能描述

创建新的客户档案，录入客户基本信息。

#### 2.4.2 业务规则

1. 企业名称为必填项
2. 客户等级默认为C级
3. 客户状态默认为ACTIVE
4. 系统自动生成客户编号
5. 创建后客户进入公海池

#### 2.4.3 输入项

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| companyName | String | 是 | 企业名称，最大200字符 |
| creditCode | String | 否 | 统一社会信用代码，18位 |
| registeredCapital | BigDecimal | 否 | 注册资本 |
| establishedDate | Date | 否 | 成立日期 |
| customerLevel | String | 是 | 客户等级：A/B/C |
| ownerId | Long | 否 | 负责人ID |
| remark | String | 否 | 备注，最大500字符 |

#### 2.4.4 输出项

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Long | 客户ID |
| customerCode | String | 客户编号 |

#### 2.4.5 界面原型

### 2.5 编辑客户

#### 2.5.1 功能描述

修改已有客户的信息。

#### 2.5.2 业务规则

1. 企业名称不可修改（如需修改需特殊权限）
2. 客户编号不可修改
3. 记录修改时间和修改人
4. 修改后同步更新关联数据

#### 2.5.3 输入项

同新增客户，id为必填。

#### 2.5.4 输出项

无

#### 2.5.5 验收标准

1. 数据回显正确
2. 修改保存成功
3. 修改日志记录完整

---

### 2.6 删除客户

#### 2.6.1 功能描述

删除客户档案（软删除）。

#### 2.6.2 业务规则

1. 采用软删除，数据保留
2. 有关联数据的客户需确认
3. 删除后客户进入回收站
4. 支持批量删除

#### 2.6.3 输入项

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 客户ID |

#### 2.6.4 输出项

无

#### 2.6.5 验收标准

1. 删除前二次确认
2. 软删除标记正确
3. 关联数据处理正确
4. 批量删除功能正常

---

### 2.7 联系人管理

#### 2.7.1 功能描述

管理客户的联系人信息。

#### 2.7.2 业务规则

1. 一个客户可以有多个联系人
2. 支持设置主要联系人
3. 联系人信息包括姓名、职位、电话、邮箱等

#### 2.7.3 输入项

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| customerId | Long | 是 | 客户ID |
| contactName | String | 是 | 联系人姓名 |
| position | String | 否 | 职位 |
| department | String | 否 | 部门 |
| mobile | String | 否 | 手机号 |
| email | String | 否 | 邮箱 |
| isPrimary | Boolean | 否 | 是否主要联系人 |

#### 2.7.4 输出项

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | Long | 联系人ID |
| contactName | String | 联系人姓名 |
| position | String | 职位 |
| mobile | String | 手机号 |
| isPrimary | Boolean | 是否主要联系人 |

| failDetails | List | 失败详情 |

## 三、非功能需求

### 3.1 性能需求

| 功能 | 响应时间 | 并发数 |
|------|---------|--------|
| 客户列表查询 | < 3秒 | 100 |
| 客户详情加载 | < 2秒 | 100 |
| 客户保存 | < 1秒 | 50 |
| 客户导入 | < 30秒（1000条） | 10 |

### 3.2 安全需求

1. 数据权限控制：销售人员只能查看自己负责的客户
2. 敏感信息脱敏：手机号、邮箱等脱敏展示
3. 操作日志记录：记录所有增删改操作

### 3.3 可用性需求

1. 界面响应流畅，无卡顿
2. 表单验证友好，错误提示明确
3. 支持键盘快捷键操作
