## 📊 文档核心内容

### 一、顶级设计开发方案 (983行)

#### 1. 项目愿景与目标
- ✅ 核心定位:轻量级本地化CRM,支持客户全生命周期管理
- ✅ 核心价值:提升销售效率、降低流失、优化资源、数据驱动
- ✅ 成功标准:跟进及时率>90%、续约率>80%、转化率提升>20%

#### 2. 技术架构设计
```
前端层: Vue3 + ElementPlus + TypeScript + Vite
  ↓ HTTP/WebSocket
后端层: FastAPI + vue-fastapi-admin + SQLAlchemy 2.0
  ↓ 异步ORM
数据层: PostgreSQL 16 + Redis 7 + pgvector
  ↓ HTTP API
自动化: n8n工作流引擎 + APScheduler定时任务
```

#### 3. 技术栈选型原则
- 成熟度: GitHub Stars > 10k
- 许可证: 宽松开源(MIT/Apache-2.0)
- 性能: 异步支持,适合高并发
- 可维护性: 类型安全,文档完善

#### 4. 核心业务规则 (6大机制)

**① 权限体系**
- RBAC角色权限(6种角色)
- 行级数据权限(个人/部门/全公司)
- 字段级权限(敏感信息脱敏)

**② 三级资源池**
```
公海池 → 团队池 → 个人池
4种回收规则: 未跟进/未转化/低效/超量
保护期机制: 7天保护 + 续约保护 + 申诉
```

**③ 5维防撞单**
- 信用代码精确匹配
- 公司名称模糊匹配(Levenshtein)
- 手机号/邮箱/电话查重
- 4种防撞单策略: 先占先得/活跃优先/联合跟进/主管强制

**④ 自动化工作流引擎**
- 4种触发条件: 时间/状态/行为/阈值
- 6种执行动作: 创建任务/发送通知/生成文档/更新数据/升级预警/分配客户
- 6个预置规则模板

**⑤ 制造业价格计算器**
```
最终价格 = 面积 × 单价 × 数量 × (1 + 损耗率) + 工艺费用
- 损耗率: 纸箱5%/纸袋8%/彩印3%/软包装6%
- 工艺: 覆膜/烫金/UV/压纹/模切
```

**⑥ 健康度评分模型**
- 5维度: 使用频率(25%)+服务交互(20%)+支付行为(25%)+跟进响应(15%)+合作稳定(15%)
- 4等级: 优秀(80-100)/良好(60-79)/风险(40-59)/危险(0-39)
- 6种场景行动计划对照表

#### 5. 开发流程规范
- 分支管理: main → develop → feature/*
- 代码规范: Black + Ruff + MyPy (Python), Prettier + ESLint (TS)
- 测试要求: 单元测试>80%, 集成测试100%, E2E核心流程
- API设计: RESTful规范,统一响应格式

#### 6. 部署架构
- Docker Compose一键部署
- PostgreSQL 16 + Redis 7 + n8n + Nginx
- 环境变量管理(.env)
- 自动备份策略(pg_dump每日)

**第一阶段:核心功能 (Day 1-25)**

## 📌 关键设计决策

### 1. 为什么选择FastAPI而不是Django?
- **性能**: FastAPI异步性能是Django的10倍+
- **AI生态**: Python AI库完美集成(LangChain/LlamaIndex)
- **开发效率**: 自动生成Swagger文档,类型安全
- **适合场景**: API密集型,AI集成需求

### 2. 为什么选择PostgreSQL而不是MySQL?
- **JSONB**: 灵活的半结构化数据存储
- **pgvector**: AI向量检索原生支持
- **全文检索**: pg_trgm扩展支持模糊搜索
- **CTE查询**: 递归查询组织架构

### 3. 为什么自研审批流和工作流引擎?
- **灵活性**: 完全适配业务需求
- **可控性**: 不依赖第三方服务
- **集成度**: 与系统深度整合
- **成本**: 零额外费用

### 4. 为什么使用n8n而不是Airflow?
- **可视化**: 拖拽式工作流编排
- **轻量**: 适合100人规模
- **集成**: 55k Stars,社区活跃
- **易用**: 非技术人员也可配置
