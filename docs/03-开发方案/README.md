## 🎓 最佳实践

### 1. 任务管理

✅ **推荐做法**:
- 每日更新任务状态
- 遇到阻塞立即上报
- 完成任务后及时打勾
- 备注关键信息(版本号、问题、解决方案)

❌ **避免做法**:
- 批量更新(容易遗漏)
- 隐藏问题不报
- 任务拆分过大(>3天)
- 不写备注

### 2. 代码开发

✅ **推荐做法**:
- 先写测试,再写代码(TDD)
- 小步提交(每次<200行)
- 提交信息规范(type: subject)
- 代码审查后再合并

❌ **避免做法**:
- 一次性提交大量代码
- 跳过测试
- 提交信息不明确
- 直接推送到main分支

### 3. 文档维护

✅ **推荐做法**:
- 代码变更同步更新文档
- API变更更新Swagger
- 重要决策记录ADR
- 定期回顾文档准确性

❌ **避免做法**:
- 文档与代码不一致
- 只有代码没有注释
- 重要逻辑没有说明
- 过期文档不更新

## 🆘 常见问题

### Q1: 任务清单太长,如何快速定位?

**A**: 使用Markdown编辑器的目录功能,或搜索任务ID(如"1.1.1")

### Q2: 多人同时编辑冲突怎么办?

**A**: 
- 方案1: 使用Git,每人负责独立模块
- 方案2: 使用在线协作工具(飞书/Notion)
- 方案3: 使用项目管理工具(Jira/Trello)

### Q3: 任务需要调整如何处理?

**A**:
1. 在任务备注说明调整原因
2. 更新验收标准(如有变化)
3. 通知相关人员
4. 记录变更日志

### Q4: 如何导出进度报告?

**A**:
- 手动: 复制Markdown表格到Excel
- 自动: 使用脚本解析Markdown生成报告
- 工具: 导入到项目管理工具自动生成
